# Roadmap: WELL DOM / prorab-sistem — рефакторинг

Карта срезов, не спека. Каждый срез потом — свой kit.

## Эпик

Система учёта для прорабов (WELL DOM): PWA + FastAPI + Capacitor. Нужен **структурный** рефакторинг без смены пользовательского поведения. Один PR «переписать всё» запрещён: нет тестового замка.

**Preserve (весь эпик):** вход по телефону+PIN, роли/права, проекты, расходы/оплаты/мастера/задачи/фото, админка, текущие URL `/api/v1/*` и поля ответов, пока срез явно не меняет контракт.

## Порядок

1. **S1 — текущий срез** (лента рефакторинг/e2e: сначала тесты).
2. S2 (security) сразу после S1 — Blocker-класс.
3. S3 ‖ S7 после S1 (разные файлы).
4. S4 после S3.
5. S5 после S1; S6 после S5.

Не начинать S5 без S1: 7k HTML без замка = тихий регресс.
